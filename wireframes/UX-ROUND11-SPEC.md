Audience: the Claude agent that will implement this. Every decision below is final (the owner reviewed the wireframes and the live prototype); ask only about technical blockers.

Rounds 1–9 and 12 precede this and must be **merged** first. Round 10 is **not** required. **Source of truth for look and behavior:** `round11-prototype.html` (one clickable file, app tokens, light + dark). ## The one architectural decision (read first)

**Every building is its own spreadsheet («فضای کاری»).** The app already supports several spreadsheets (`settings.spreadsheets`, `setActiveSpreadsheet` in `src/services/settings.ts`, `activateSpreadsheet` in `src/services/spreadsheetSetup.ts`, every localStorage key per spreadsheet, backup / close-the-year / sharing / search per spreadsheet). A building spreadsheet uses the **same engine** (records with categories, subcategories, line items, attachments and counterparties; wallet accounts; receivables; dang; checks; recurring items; bank SMS; reports; activity log; conflicts) but a **different menu and dashboard**, selected by a workspace type marker. Nothing of the building ever touches the manager's personal spreadsheet: no shared counterparties, no fund money in the personal net-available, no building categories in personal reports, no building rows in the personal widget. Sharing a building with board members = Drive sharing of that one spreadsheet (round 8 writer/activity/conflicts apply as is).

Two deliberate **bridges** between a building and the manager's personal spreadsheet exist (Step 8); nothing else crosses.

## Model

| Concept | Where it lives (inside the building spreadsheet) |
|---|---|
| Workspace type | «تنظیمات دوره» row `نوع فضا = ساختمان`; the spreadsheet title is «حسابداری · ساختمان <name>» so Drive listing still finds it |
| Building profile | new tab `BUILDING_SHEET = 'ساختمان'` (one row): `نام, نشانی, طبقات, شارژ پیش‌فرض, روش شارژ (fixed\|area\|people), روز صدور, سررسید (روز), شارژ واحد خالی (full\|half\|zero), زمان ویرایش` |
| Unit | new tab `BUILDING_UNITS_SHEET = 'واحدها'`: `شناسه, زمان ثبت, شماره, طبقه, متراژ, نفرات, پارکینگ, انباری, شارژ ماهانه (0 = follow the building method), فعال, یادداشت` |
| Resident / owner | new tab `BUILDING_RESIDENTS_SHEET = 'ساکنان'`: `شناسه, زمان ثبت, شناسه واحد, شناسه طرف حساب, نقش (owner\|tenant), تاریخ ورود, تاریخ خروج, فعال` — one row per person per stay; people are **counterparties of this spreadsheet** (name, phones, bank cards; `placeholder: true` until completed; `me: true` for the manager's own person) |
| Fund | **all** wallet accounts of this spreadsheet (bank with card digits, or cash); no flag needed |
| Monthly charge | a **receivable** per unit per month: `debtor` text + new last columns `مرجع` («charge:<unitId>:<YYYY-MM>», «share:<unitId>:<recordId>», «opening:<unitId>», «credit:<unitId>») and `شناسهٔ بدهکار` (counterparty id — display resolves the name from the id; the counterparty rename flow also rewrites the text), `category` «شارژ ساختمان» (system), `title` «شارژ <month> · واحد <no>», `amount`, `borrowDate` = due date |
| Charge payment | receivable payment → income record into a fund account (round-9 settle flow); **overpayment becomes unit credit** (an income record with `مرجع` = `credit:<unitId>`), applied at the next issue |
| Expense | a full **expense record** (category/subcategory from the building category list, line items, attachments, counterparty = contractor, recurring, duplicate check) + new last columns on the record tabs: `نوع هزینه` (a key of the managed `EXPENSE_KINDS` list), `تقسیم` (JSON `{ mode, shares: {[unitId]: amount}, charge: boolean }`), `پرداخت‌کننده` (a key of the managed `EXPENSE_PAYERS` list) |
| Debt to the manager / a member / a contractor | **dang** rows (`counterparty` = the payer or the contractor); settled from the fund with the settle sheet, which writes a **transfer** («انتقال › بازپرداخت به <payer>»), never a second expense |
| Fund correction | a `correction` record (signed amount, system category «اصلاح موجودی») written only by the reconcile sheet; skipped by reports and «وصول − هزینه» like transfers |
| Other income | income records (parking, rooftop lease, bank interest, penalties, donations) with the building income categories |
| Statement / receipt | computed from receivables + payments + credit; rendered as text and PNG |
| Roles | «تنظیمات دوره» rows `نقش:<email>` = `manager \| accountant \| board` (+ optional `دسترسی:<email>` JSON overrides) |
| Managed lists | «تنظیمات دوره» rows `فهرست:<id>` = JSON `[{ value, label, chargeTo?, hidden? }]` for `EXPENSE_KINDS` and `EXPENSE_PAYERS` |
| Issue marker | «تنظیمات دوره» row `آخرین صدور = <YYYY-MM>@<deviceId>@<ISO time>` (concurrency guard) |

Default category lists for a building workspace (replace the personal defaults at creation): **expense** آسانسور (سرویس، تعمیر، بیمه) · نظافت (نظافتچی، مواد شوینده) · قبوض مشاعات (برق، آب، گاز) · تعمیرات (تأسیسات، ساختمانی، برق‌کشی، پمپ و مخزن) · حقوق سرایدار · بیمه ساختمان · عوارض و شهرداری · اداری (پرینت، پیک، کارمزد) · فضای سبز · ایمنی و اطفاء · انتقال [system] · اصلاح موجودی [system] · سایر; **income** شارژ ساختمان [system] · پارکینگ مهمان · اجارهٔ مشاعات (پشت‌بام، آنتن، انباری) · سود سپرده · جریمه · کمک مالی · طلب [system] · سایر.
